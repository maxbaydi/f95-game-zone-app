# Аудит UX и автоматизации: что уже само, что сделано в 1.7.0, что осталось

**Статус:** active
**Дата аудита:** 2026-09-29
**Источники:** `tasks.md` (все «What is left»), `docs/*.md`, `docs/adr/*.md`, код `src/main.js`, `src/main/**`, `src/core/**`; `issues.txt` был пуст, маркеров TODO/FIXME в `src/` нет.

## Зачем
Пользователь не должен помнить, что нужно нажать. Всё, что можно сделать за него в фоне, делается в фоне; всё, что требует его участия, показывается компактно и рядом с местом действия. Этот документ — единый список: что приложение уже делает само, что закрыто в 1.7.0 и что остаётся в очереди с оценкой.

## Уже работало само до 1.7.0 (не предлагать повторно)
- Живые проверки тем F95 (`liveUpdateCheck.js`): через 90 с после запуска, через 10 с после входа в F95, затем каждые 6 ч; только избранные, по одной теме, до 40 за прогон; системное уведомление о найденном обновлении.
- Сверка сохранений с хранилищем (`saveStorageSync.js`): через 20 с после запуска, после установки/обновления, после подключения/разблокировки; после запуска игры её папки под наблюдением, 90 с тишины → выгрузка; история из 5 архивов.
- Проверка обновления приложения и каталога Atlas один раз при старте; уведомления «доступно» и «готово к установке».
- Перепроверка наличия файлов при возврате фокуса окну (если прошло больше 60 с).
- Загрузки: список переживает перезапуск, очистка `_staging` и сирот при старте, пакет удаляется после успешной установки, история до 40 записей, докачка по Range внутри сессии, до 3 запасных зеркал, автопродолжение после капчи/Cloudflare (15 мин).
- Досчёт размеров папок через 1,2 с после запуска; трей с пунктами «Check for App Updates» / «Refresh Library Updates».

## Осталось в очереди (по убыванию пользы)
1. **Ограничение параллельных загрузок и пауза.** Сейчас каждая установка стартует сразу; нет паузы и переупорядочивания (`main.js` `runF95DownloadContext`). Нужна очередь с лимитом 2 и кнопка «Pause».
2. **Возобновление загрузки после перезапуска приложения.** Активная запись превращается в «Interrupted», `.part` удаляется при старте. Docker‑докачка по Range уже есть (`directDownload.js`, `resumeFrom`), не хватает сохранения `.part` и повторного запуска.
3. **«Update all»** для раздела Updates: очередь по одной игре, как у «Reinstall all» (`missingGamesActions.js`) + `Recommended` зеркало из `inspect-f95-thread`.
4. **Автоповтор неудачной загрузки** позже по времени (например, через 10 мин, до 3 раз) для сетевых ошибок; сейчас только Retry.
5. **Очередь одобрения в Scan Hub**: массово «добавить / игнорировать» для «need review» и «Not matched», сейчас по одной через «Link to catalog…».
6. **Очистка мусорных записей после скана**: `cleanupLibraryNoiseRecords` готова, но нигде не вызывается; безопасный вариант — предлагать в итогах скана.
7. **Автопоиск переехавшей папки** для «Files missing»: искать по имени папки в папках сканирования до предложения «Locate…».
8. **Конфликты сохранений**: диалог «на этом ПК / в хранилище» с датами и размером вместо пилюли «Review needed»; просмотр и восстановление из истории (5 архивов уже хранятся, IPC нет).
9. **Периодическая синхронизация сохранений** (например, каждые 30 мин), а не только после запуска игры из приложения.
10. **«Установить и восстановить»** из каталога бэкапов для игр, которых нет в библиотеке.
11. **Хосты с Turnstile/Adscore** (Mixdrop, Krakenfiles, DataNodes шаг 2 …) — только с человеком; можно хотя бы заранее помечать такие зеркала как «ручные» в выборе.
12. **Удаление мёртвых ключей конфига** (`Interface.atlasStartup`, `gameStartup`, `Performance.maxHeapSize`, `Metadata.downloadPreviews`) и старого окна `settings.html`.
13. **Ручной smoke на Windows**: трей в упакованной сборке, уведомления при Focus Assist, autostart с `--hidden`, авто‑установка обновления при выходе.
